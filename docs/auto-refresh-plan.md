## Decisions

- Auto-refresh is **status-only**. It never syncs, force-syncs, or changes a
  working tree.
- `background_mode = false` by default: closing the window quits.
- `auto_refresh_s = 0` by default: automatic status refresh is off.
- When enabled, the GUI presets **15 minutes**.
- Hard floor: **5 minutes (300 s)**. Values from 1–299 s are clamped to 300 s
  with a warning. `0` means off.
- Orange warning below 15 minutes: frequent fetches increase load on remote
  servers.
- Manual status, sync, and force-sync cancel the pending auto timer; after the
  run finishes, the next auto refresh is a full interval away.
- Jitter: 0–60 s. Backoff on errors: double, capped at 1 hour, reset on success
  or a manual run.
- Automatic and manual runs never overlap. A CLI run holding the run lock
  causes the auto attempt to fail and back off.
- Background mode uses **close-to-tray**. Normal minimize stays in the taskbar.
- Tray icon is symbolic (white/alpha mask) on Bazzite/KDE, with the full mark as
  fallback. Tray menu: Open, Refresh status now, Pause/Resume automatic refresh,
  Quit. No Sync from the tray.
- Single GUI instance: a second launch says repopull is already running and
  exits.
- Version **0.4.0**.

## Configuration

```toml
background_mode = false
auto_refresh_s = 0
```

- `background_mode`: bool; keep the app resident in the tray after the window is
  closed.
- `auto_refresh_s`: integer; `0` off; otherwise at least 300 s. The GUI edits
  minutes.
- `save_config` writes both keys.
- `config.example.toml` and `packaging/default-config.toml` document both.
- `docs/configuration.md` owns the key reference; `docs/gui.md` owns the
  Settings layout.

## Scheduler

A small pure module (planned `src/repopull/refresh.py`) owns:

- floor/recommended/max constants;
- `clamp_auto_refresh_s()` and `should_warn()`;
- backoff/jitter calculation;
- cooldown calculation.

The GUI uses one **single-shot** `QTimer`, rescheduled after every run. It never
uses a repeating timer that can stack. It schedules `base + jitter` after the
last network run, checks the cooldown again when the timer fires, and skips if a
task is active or the app is quitting. Auto-refresh starts a status task only.

## Settings and tray

Settings → **Background & refresh**:

- `[ ] Keep running in the system tray when the window is closed`
- `[ ] Refresh status automatically`
- `Every [15] minutes` (5–1440), disabled when auto-refresh is off
- orange warning when enabled below 15 minutes
- note: “Status only — automatic refresh never syncs.”

Tray:

- symbolic `repopull-symbolic.png` generated by `packaging/make_icon.py` at
  16/22/24/32, used with `QIcon.setIsMask(True)`;
- fallback to the normal mark;
- one tray icon and one menu for the lifetime of the window;
- `QSystemTrayIcon.isSystemTrayAvailable()` check; when unavailable, background
  mode is disabled with a warning and close quits;
- background on: close hides to tray; Tray → Quit runs the graceful shutdown;
- background off: close quits; if auto-refresh is on, it runs only while the
  window is open;
- tray tooltip shows the last result and next refresh.

## Durability and shutdown

- The run lock already uses `fcntl.flock`; the OS releases it on process death
  or power loss. A leftover `.lock` file is harmless, not a held lock.
- Make `latest.log`, `latest.json`, and timestamped run logs atomic: temp file
  in the same directory, flush/fsync, `os.replace()`, clean up temp files.
- Config saving is already atomic.
- Graceful shutdown: stop the timer, set `RunTask.cancel`, wait for the current
  repository to finish, release locks, hide the tray, then quit. No force-kill
  of git.
- `closeEvent`, `aboutToQuit`, and SIGTERM/SIGINT follow the same path.
- Power loss during a sync: no auto-repair or auto-reset. The next status
  reports the state; config and `latest` state are atomic.
- Single-instance guard uses a Qt lock file for the GUI process lifetime; the
  per-run lock remains separate so the CLI can run while the GUI is idle.

## Memory and long-running checks

- One timer, one tray icon, one menu; no per-cycle widget/timer/tray creation.
- `RunTask` clears references on finish; `QThreadPool` stays at one worker.
- Log retention (0.3.0) keeps disk bounded.
- Add a scheduler soak test (hundreds of cycles) and a GUI run-loop check with
  `gc`/`tracemalloc`.
- Do not retain report history in memory beyond the current/latest snapshot.

## Out of scope

- Login/autostart (systemd user service).
- Desktop notifications (tray tooltip only for now).
- Auto-sync or tray-triggered sync.
- Log compression/archiving.
- Minimize-to-tray; this plan uses close-to-tray only.
